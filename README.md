# Payphone reverse engineering project

This repo contains the reverse engineering project of the TAMAC18-model Israeli Payphone.

The repo includes the ROMs, the Ghidra CPU definition and (soon) the Ghidra project.

## Contents

- [`cdp1806/`](cdp1806/) — Ghidra CPU definition for the CDP1806, plus the
  inline-argument and SCRT call analyzers.
- [`phone/TAMAC18-firmware.md`](phone/TAMAC18-firmware.md) — reverse
  engineering notes for the TAMAC-18 payphone firmware (CDP1806ACE): the
  `P = R4` convention, the interrupt system, the card reader link protocol from
  the phone's side, how the card is debited, and the dial-up session that
  uploads call records to **Isranet**, the Israeli X.25 gateway.
- [`card-reader/BSK31-firmware.md`](card-reader/BSK31-firmware.md) — reverse
  engineering notes for the Landis & Gyr BSK31-202 optical phonecard reader
  (CDP1802) used by the payphone, including its wire protocol.
- [`phone/RAM-MAP.md`](phone/RAM-MAP.md) — every RAM cell the firmware
  points a register at, with its name or, where it has none, the signature the
  ROM shows for it. Generated by [`tools/ram_map.py`](tools/ram_map.py).
- [`OPEN-QUESTIONS.md`](OPEN-QUESTIONS.md) — the running queue of what is
  still unknown, what evidence bears on it, and what would settle it.
- [`tools/dis.py`](tools/dis.py) — a linear CDP1802/1805/1806 disassembler for
  the image.

  **Read code through Ghidra first.** Ghidra holds the function boundaries, the
  names already established and the real cross-references, and it is the view
  the listing in these notes is supposed to match. This script is for the cases
  Ghidra cannot cover or gets wrong: code with no function defined — common in
  this image, where `05A6`, `0699`, `067E`, `70B9`, `7014` and `3B24` all have
  none — sites where the `X == P` inline-operand form or an uncovered inline
  `SCAL` argument makes the listing actively wrong, and image-wide scripted
  scans such as "every `RLDI R1`" or "every inbound reference into this range".
  Where both can see the same code, cross-check: reading `5E1B` here stopped at
  `5E60` when Ghidra has the function ending at `5E6D`.

  It exists because hand-counting bytes produced several of the
  errors these notes have had to retract, and it handles the two things a naive
  sweep gets wrong here: the `X == P` inline-operand form, where `OUT`/`RET`/
  `DIS`/`LDXA`/`IRX` take an operand from the instruction stream and are two
  bytes instead of one, and inline call arguments, where the bytes after a
  `SCAL` are data and decoding them as code invents plausible instructions.
  Argument signatures come from
  [`cdp1806/data/inline_args.txt`](cdp1806/data/inline_args.txt), and are
  otherwise inferred from the callee's own prologue the way the Ghidra analyzer
  does. `--selftest` checks a table of hand-verified decodes.
- [`tools/dump_strings.py`](tools/dump_strings.py) — dumps the firmware's
  Hebrew and Latin strings, and walks LCD descriptor chains. Handles the
  ROM's `0xA0`-based Hebrew encoding and its per-string byte order.

## External corroboration

The phone uploads its call records over **Isranet**, Israel's X.25 network,
dialled on `131`. Phrack 27's [NUA list for Datex-P and X.25
networks](https://phrack.org/issues/27/nua-list-for-datex-p-and-x25-networks)
(1989) gives Israel's DNIC as `0425` and Isranet as `04251`, and its one Israeli
address — `0425 130 000 215` — has an eight-digit national part. The NUA this
firmware calls, `34011503`, is eight digits with the same leading `3`, sent bare
as a same-network address. See
[`phone/TAMAC18-firmware.md`](phone/TAMAC18-firmware.md) §10at.
